## 3. 模块边界与接口

### 3.1 数据与模型（A）

- 输入：DEM 瓦片、OSM 要素、ERA5 降雨、官方阈值；
- 输出：`terrain.json`、`buildings.json`、`vectors.json`、`sensors.json`、`scenarios/*.json`；
- 关键约束：网格 192×136、10 min 帧、49 帧、深度 Uint8（cm）、base64 编码；
- 验收：三情景无 NaN；水量闭合率 ≥0.85；峰值量级合理；报告数字与 JSON 一致。

### 3.2 三维与前端（B）

- 输入：上述 JSON + `meta.json`；
- 输出：`src/scene.js`、`city.js`、`water.js`、`rain.js`、`markers.js`、`main.js`；
- 关键约束：不引入网络 CDN；Three.js 本地化；WebGL2；1600×900 目标 30 fps+；
- 验收：情景切换/时间轴/图层/点位/视角五类交互可用；无控制台报错；截图可进报告。

### 3.3 平台与集成（C）

- 输入：JSON 契约；
- 输出：`server.mjs`、`/api/*`、部署脚本、测试报告；
- 关键约束：零依赖、单命令启动、静态资源 gzip、JSON 不被缓存；
- 验收：`/api/health`、`/api/scenarios`、`/api/warnings`、`/api/dispatch` 返回正确；断网本地可跑。

### 3.4 产品与表达（D）

- 输入：系统截图、报告、模型结果；
- 输出：界面规范、PPT、3 min 视频、答辩稿；
- 关键约束：不夸大精度；数据边界必须出现；视频 ≤3 min；
- 验收：PPT 14 页无溢出；视频 2:45 左右、音画同步；答辩 8—10 min 内完成。

## 4. 协作机制

### 4.1 Git 工作流

- `main`：随时可演示；`dev`：集成；`feature/<module>-<desc>`：开发；
- 提交信息：`feat(water): 增加雨滴涟漪`、`fix(api): 修正 t 越界`、`docs(report): 补充数据边界`；
- 每个 PR 至少 1 人 review；合并前跑 `node --check`、数据完整性脚本、页面冒烟测试；
- 大文件（JSON/视频/PPT）不进 Git 历史，用网盘/Release 管理。

### 4.2 接口契约

- 第 2 周冻结 `sensors.json`、`terrain.json`、`scenario.json` 字段；
- 字段变更顺序：改 `报告附录 A` → 改代码 → 通知全员；
- 前端先用 mock 数据，后端按契约实现；联调只对契约不对人。

### 4.3 会议与看板

- 周一 30 min 计划会；周四 30 min 风险会；每天 10 min 站会；
- 看板四列：待办 / 进行中 / 待评审 / 完成；每人同时最多 2 个进行中任务；
- 关键路径（数据、模型、联调）红标，延期 1 天升级队长。

### 4.4 联调与验收

- 每周五下午固定联调，产出“可运行版本 + 截图 + 已知问题”；
- 验收按 FR1—FR6 逐条演示；数据无 NaN；页面无报错；报告数字与系统一致；
- 答辩前 48 h 冻结代码，只修 P0；准备离线包、备用录屏、两台电脑。

## 5. 六周计划

| 周次 | A 数据/模型 | B 三维/前端 | C 平台/集成 | D 产品/表达 | 里程碑 |
|---|---|---|---|---|---|
| 第 1 周 | 需求、数据源核验、DEM/OSM 抓取 | Three.js 场景骨架、相机 | 静态服务、目录结构 | 竞品分析、视觉规范 | 数据可用、场景可跑 |
| 第 2 周 | 数据清洗、建筑高度、传感器选址 | 地形/建筑/路网 | JSON 契约、API 雏形 | 界面线框、图标 | 数字底座完成 |
| 第 3 周 | SCS-CN/二维模型、情景率定 | 水面 Shader、雨幕 | 情景 API、预警规则 | 面板视觉、交互稿 | 首个情景可推演 |
| 第 4 周 | 三情景输出、结果分析 | 传感器/标注/后处理 | 测试、性能、部署 | 联调 UI、截图 | 系统 80% |
| 第 5 周 | 报告数据/图表/统稿 | 性能优化、兼容 | 异常处理、API 文档 | PPT、视频脚本 | 报告初稿、PPT 初稿 |
| 第 6 周 | 报告终稿、答辩串讲 | 演示环境、备份 | 终验、部署 | 视频成片、答辩演练 | 提交 |

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 数据缺失/接口失效 | 中 | 高 | OSM API 回退、离线数据包、多源备份 |
| 模型结果不合理 | 中 | 高 | 先用 5 年情景校验量级，再跑 50 年；保留参数日志可回滚 |
| 三维性能不足 | 中 | 中 | 合并几何、关阴影、Bloom 半分辨率、像素比上限 |
| 联调延期 | 中 | 高 | 契约先行、mock 数据、每周五联调、关键路径红标 |
| 答辩现场故障 | 低 | 高 | 离线包 + 本地服务 + 备用录屏 + 两台电脑 |
| 分工不均 | 中 | 中 | RACI 明确、看板透明、队长每周复盘工时 |
